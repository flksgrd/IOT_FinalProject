\section{Testing and results}
\label{sec:testing}

We tested the system at three levels: individual components, the device-side firmware, and the full end-to-end pipeline. Where possible we repeated tests across multiple sessions to catch intermittent failures.

\subsection{Component-level tests}
\label{sec:test-components}

\begin{itemize}
    \item \textbf{HC-SR04 ultrasonic.} Measured distance against a fixed object at 5\,cm to 40\,cm, compared with a measuring tape. Agreement within $\pm$1\,cm across the range. Below \textasciitilde 3\,cm the sensor saturates and is excluded from the firmware's decision logic.
    \item \textbf{LM35 temperature.} Compared with an external digital thermometer at room temperature (\textasciitilde 21\,\textdegree C) and in warm water (\textasciitilde 35\,\textdegree C). Before calibrating the ADC reference and filtering, readings drifted by several degrees and were noisy. After calibrating the reference to 2.667\,V and applying the IIR filter, the steady-state error is within $\pm$1\,\textdegree C.
    \item \textbf{Stepper closure.} Tested both single-motor and dual-motor configurations against bags with different fill levels. The single-motor design occasionally let the bag twist; the dual-motor design closed the bag reliably across $>$20 attempts.
    \item \textbf{OLED display.} Verified that the I\textsuperscript{2}C bus works on D1/D2 once the stepper coil IN4 was moved off D1.
\end{itemize}

\subsection{Firmware-level tests}
\label{sec:test-firmware}

The state machine was exercised by manually triggering each transition:

\begin{itemize}
    \item \textsc{load} $\to$ \textsc{check}: press reset after fitting a bag. Bag counter decrements by one. \checkmark
    \item \textsc{check} $\to$ \textsc{close}: cover the sensor at $<$10\,cm. Motors run, field 4 goes high on ThingSpeak. \checkmark
    \item \textsc{close} $\to$ \textsc{empty\_me}: motors stop after the fixed step count, OLED prompts to replace the bag. \checkmark
    \item \textsc{empty\_me} $\to$ \textsc{load}: reset button returns the system to the start state. \checkmark
    \item \textsc{check} $\to$ \textsc{help} on overfill: forced an out-of-range reading; system entered \textsc{help} as expected. \checkmark
\end{itemize}

\subsection{End-to-end pipeline test}
\label{sec:test-e2e}

The full pipeline was run continuously for multi-hour sessions across several lab days while the dashboard was monitored in parallel. The five acceptance criteria from our test plan:

\begin{enumerate}
    \item ESP push is reflected on the dashboard within 5--16\,s. \checkmark
    \item A new bag count entered on the dashboard reaches the ESP within 50\,s worst-case. \checkmark
    \item Bag-full event arrives as a phone notification within \textasciitilde 30\,s. \checkmark
    \item Low-bags event (\texttt{field2 $<$ 3}) arrives as a phone notification. \checkmark
    \item ONLINE/OFFLINE pill flips to OFFLINE within \textasciitilde 90\,s of unplugging the ESP. \checkmark
\end{enumerate}

All five scenarios passed across repeated runs. The measured latencies match the theoretical worst case derived from ThingSpeak's free-tier rate limits.

\subsection{Remaining weaknesses}
\label{sec:weaknesses}

\begin{itemize}
    \item HTTP traffic to ThingSpeak is unencrypted. Acceptable for sensor telemetry but not for production.
    \item Hard-coded WiFi credentials in the firmware. A real product would use a captive-portal provisioning flow.
    \item ThingSpeak free-tier limits push cadence to one update per 15\,s. For a domestic kitchen bin this is more than enough, but a commercial multi-bin deployment would hit the limit fast.
    \item The bin-full threshold is fixed at 10\,cm. A real product would let the user calibrate it for different bin geometries.
\end{itemize}

\subsection{Future development}
\label{sec:future}

Natural next steps include: switching ThingSpeak for a self-hosted MQTT broker with TLS; adding a battery and a deep-sleep mode so the bin does not need a USB cable; replacing the LM35 with a combined humidity/gas sensor for organic-waste warnings; adding a small mobile app instead of relying on the IFTTT push channel; and a fleet management view for households with multiple bins.

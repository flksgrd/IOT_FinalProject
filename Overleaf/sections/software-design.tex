\subsection{Software design}
\label{sec:software}

The software has four layers -- firmware on the ESP8266, a ThingSpeak channel that mediates between everyone, the static web dashboard hosted on Netlify, and IFTT web app implementation for pushing notifications on a phone -- and each layer is independent: if any one of them is restarted, the others keep working.
\\ \\
The firmware itself is written in Arduino C++ and is structured by a state machine in the main loop. The State machine is controlled by the variable \texttt{current\_state}, the state variable can hold the enum values of (\texttt{LOAD}, \texttt{CHECK}, \texttt{CLOSE}, \texttt{EMPTY\_ME}). The States make the code easier to control and ensures the ESP only works on relevant tasks.\\\\
In the \texttt{LOAD} state, the \texttt{LM35()} function is continuously run which is used to measure the temperature. The temperature is measured by using the 10-bit ADC to convert the analog Voltage value from the output of the LM35 to a digital 10-bit value, to make this value match the actual temperature, The ADC value has been calibrated using a thermometer as a reference. \\\\
However, the theoretical reference voltage of $3.3\text{V}$ used in the standard conversion formula was very inaccurate in our temperature output. We found that the inaccuracy is mainly due to the tolerances of the internal resistors making up the voltage divider on the board. The chip has an internal reference voltage of $0-1\text{V}$, while the board accepts $0-3.3\text{V}$. To compensate for these hardware-specific issues, a single-point calibration was performed.\\\\
The calibrated scaling factor is determined by comparing the initial temperature read by the system ($T_{read}$) to a known reference temperature ($T_{ref}$) measured with a precise external multimeter. The new calibration factor is calculated using the following equation:

\begin{equation}
    Factor_{cal} = \left( \frac{T_{ref}}{T_{read}} \right) \cdot Factor_{the}
\end{equation}
For this specific hardware setup, an initial measurement using the theoretical factor of $3.3$ yielded a reading of $31.3^\circ\text{C}$, while the actual reference temperature was measured to be $25.3^\circ\text{C}$ (We measured $253\text{mV}$ with a multimeter on our mounted LM35). Inserting these values into the formula yields the calibrated factor:

\begin{equation}
    Factor_{cal} = \left( \frac{25.3}{31.3} \right) \cdot 3.3 \approx 2.667
\end{equation}

\noindent This calibrated factor of $2.667$ replaces the theoretical $3.3$ multiplier in the conversion formula in the code. By implementing this corrected scaling factor, the linear relationship is almost restored, ensuring that the raw 10-bit ADC values are more accurately translated into the correct ambient temperature.
\\\\
\noindent To smooth the displayed temperature a moving average 10 sample first order IIR filter has been implemented which has the theoretical design of:
\[
y[n] = 0.3x[n] + 0.7y[n-1]
\]\\
This blends the current measured temperature with the previously calculated temperature at a 30/70 ratio. 
\\
In the \texttt{LOAD} state the ESP is polling whether the button has been pressed including a debounce functionality to make sure that the press was deliberate. When the button is pressed the moveBackward() function is run and the motors load the strings of the trashbag. The button press also sets the state  variable to \texttt{CHECK} which makes the code run the \texttt{CHECK} State. \\\\
In the \texttt{CHECK} state the ESP samples the distance with the use of the ultrasonic distance sensor in the \texttt{UltraSense()} function with the HC-SR04. The distance is sampled by measuring the time between the sent trigger pulse and when the echo is received. in this state the \texttt{LM35()} function is also run which is described in the \texttt{LOAD} State. If the distance measured by the HC-SR04 sensor is 8cm or below the State variable is set to the \texttt{CLOSE} State which makes the ESP run the \texttt{Close} state code.\\\\
In the Close State the \texttt{moveBackwards()} function which makes the Stepper motors pull the strings till full closure. When this task is done the state machine automatically enters the \texttt{EMPTY\_ME} State. 

In the \texttt{EMPTY\_ME} State the ESP polls whether the button has been pressed including a debounce to make sure the press was deliberate. When the button has been pressed the moveForwards() function is run and the stepper motors release the trash bag strings and the State variable is set to the \texttt{LOAD} State.
\\\\
After each state transition the ESP pushes the current values -- distance, bags remaining, state, bag-full flag and temperature -- to ThingSpeak.
\\ \\
ThingSpeak channel 3364403 acts as the single source of truth. Six of its eight fields are in use (Table~\ref{tab:fields}); the device and the dashboard read from and write to the same numbered fields rather than talking to each other directly, which is the same pattern used for the IFTTT notification path.

\begin{table}[H]
    \centering
    \begin{tabular}{c|l|l|l}
        \textbf{Field} & \textbf{Meaning} & \textbf{Written by} & \textbf{Read by} \\
        \hline
        1 & Distance (cm) from ultrasonic sensor & ESP & Dashboard \\
        2 & Bags remaining                       & ESP & Dashboard, IFTTT React \\
        3 & State (0=LOAD, 1=CHECK, 2=CLOSE, 3=EMPTY\_ME) & ESP & Dashboard \\
        4 & Bag-full event (1 = full)            & ESP & IFTTT React \\
        5 & Set-bag-count command                & Dashboard & ESP \\
        6 & Temperature (\textdegree C) from LM35 & ESP & Dashboard \\
    \end{tabular}
    \caption{ThingSpeak field map}
    \label{tab:fields}
\end{table}
